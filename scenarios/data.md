# Data

Patch data is generated by `pnpm data:update` (PLAN §5) and committed. Patch folders are named `<major>.<minor>` (e.g. `16.22`).

### DATA-001: Generated data is written per patch

- **Given** the manifest lists champions, items and runes
- **When** the pipeline runs for patch P
- **Then** `generated/P/` contains champion, item and rune data for exactly the manifest's entries
- **And** each file records patch P

### DATA-002: The latest patch is used by default

- **Given** no patch argument
- **When** the pipeline runs
- **Then** it uses the newest version in Data Dragon's version list

### DATA-010: Game files come from the same patch

- **Given** patch P
- **When** the pipeline fetches CommunityDragon files
- **Then** it reads them from CommunityDragon's folder for P, never `latest`
- **And** fails if that folder doesn't exist

### DATA-003: Windup from cast time and total time

- **Given** a champion attack with a cast time and a total attack time
- **When** it is normalized
- **Then** its windup percent is cast time ÷ total time

### DATA-011: Windup from cast offset

- **Given** a champion attack with no cast time but a cast offset percent O
- **When** it is normalized
- **Then** its windup percent is 0.3 + O

### DATA-012: Windup modifier

- **Given** a champion attack with a windup attack-speed ratio
- **When** it is normalized
- **Then** that ratio is stored as its windup modifier
- **And** attacks without one get a windup modifier of 1

### DATA-013: Windup is stored per attack slot

- **Given** a champion with separate normal, crit or alternate attacks (e.g. Jinx's rockets)
- **When** it is normalized
- **Then** each attack slot keeps its own windup percent and modifier

### DATA-014: Attack speed ratio and crit multiplier are copied

- **Given** a champion's attack speed ratio and crit damage multiplier in its game file
- **When** it is normalized
- **Then** both are copied, rounded to 4 decimal places

### DATA-004: Ability values are stored per rank

- **Given** a spell data value with entries for rank 0 through rank 6
- **When** it is normalized
- **Then** the ability's value list holds the entries for ranks 1 to the ability's max rank, in order

### DATA-015: Game constants are part of patch data

- **Given** game-wide rules that patches can change (attack speed cap, base crit multiplier)
- **When** the pipeline runs
- **Then** they are written to the patch's constants, from overrides where no game file has them

### DATA-016: Skill orders are hand-authored

- **Given** a supported champion
- **When** the pipeline runs
- **Then** its standard skill order (ability per level 1–18) comes from its override file
- **And** the run fails if a supported champion has none

### DATA-017: Items record exclusive groups

- **Given** items that share a unique group (e.g. Last Whisper, Lifeline, boots)
- **When** they are normalized
- **Then** each records its group names

### DATA-005: Overrides take precedence over generated values

- **Given** an override file sets a value for an item
- **When** the pipeline runs
- **Then** the written value is the override's

### DATA-006: Invalid data fails the run

- **Given** normalized data that does not match the schema
- **When** the pipeline runs
- **Then** it fails, naming the entity and field
- **And** writes nothing

### DATA-007: Missing values used by effect code fail the run

- **Given** an item effect that reads the value `damagePerStack`
- **When** the new patch's data has no `damagePerStack` for that item
- **Then** the pipeline fails, naming the item and key

### DATA-008: Drift report lists changes from the previous patch

- **Given** generated data for a previous patch
- **When** the pipeline runs for a new patch
- **Then** it reports each value that changed (old → new), and each key added or removed

### DATA-009: The app uses the newest generated patch

- **Given** generated data for several patches
- **When** the app loads
- **Then** it uses the newest patch and shows that patch number
